# 三个 driver，以及它们各自的代价

有人问「为什么不用 X」，或者 OpenCLI 这条路确实走不通时读这一篇。

结论先给：**OpenCLI 是默认，包括快速看一眼页面这种活儿。**

---

## 为什么默认是 OpenCLI

OpenCLI 通过**浏览器扩展 + 本地守护进程**够到用户自己的 Chrome。
这条路径不绑定任何一个 agent 运行时——它是一条 CLI，
所以 Claude Code、Codex、任何能跑 shell 的 agent 拿到的是完全相同的能力。

**这个可移植性是硬需求，不是锦上添花**：同一批活儿会从不同运行时跑，
一个只存在于其中一个运行时里的 driver 会让另一半工作无法复现。

| Driver | 够得到用户已登录的 Chrome | 任何 agent 运行时都能用 |
|---|---|---|
| **OpenCLI** | 是——扩展 + 守护进程 | **是**，它是 CLI |
| agent-browser | 否（当前 Chrome 上，见下） | 是，它是 CLI |
| Claude in Chrome | 是——自己的扩展 | 否，Claude 专属 MCP |

用一个运行时专属的工具去做探索，意味着这次探索**没法被脚本或另一个 agent 重放**——
而那正是我们给这些活儿写脚本的全部理由。

---

## agent-browser —— 在当前 Chrome 上够不到用户的浏览器

它通过 CDP 附加。两堵独立的墙让这件事对用户的日常浏览器不可能，
2026-08-21 在 Chrome 151.0.7922.173 上验证：

1. **Chrome 136+ 在默认 user-data-dir 上静默忽略 `--remote-debugging-port`。**
   带着这个标志重启 Chrome，`ps` 确认标志传进去了；
   `lsof -nP -iTCP -sTCP:LISTEN -a -p <pid>` 显示**根本没有监听端口**，9222 不可达。
   **重启 Chrome 是白费力气，不要建议这条。**
2. **macOS TCC 挡住读取 `~/Library/Application Support/Google/Chrome`**，
   所以把 profile 复制出来这条路也是死的。
   `agent-browser doctor` 报 `no profiles parsed` 就是这个，不是配置错了。

它的 `--profile` 指的是**它自己创建、你登录一次的独立 profile 目录**，
和用户已有的会话无关。

**本机不把它作为浏览器动作的选项，只有用户明确点名时才用。**
它的隔离是真的、且是服务端强制的：
`--session` 给每个 agent **一整个独立 Chrome 进程**
（实测三个 agent 让进程数从 2 涨到 5），彼此完全看不见对方的标签页，
4 轮 × 3 页面 × 3 agent 零抢占。**三者中最强的隔离，用最多的资源换来的。**

用它的话有两个陷阱：

- **`t1`/`t2` 这种标签页 id 是共享的位置索引，不是每个 agent 自己的句柄。**
  两个 agent 的 `t2` 解析到了同一个 CDP 目标，读取返回了对方的页面，**且没有报错**。
  **按 `--label` 寻址，绝不按位置。**
- **`--pin-tab` 的失败没有文档说的那么响。** 显式指名一个已经不存在的 label 时会正确报错，
  但不切换标签页的命令（`get url`、`snapshot`）会**静默回落**到你自己的另一个标签页。
  它防的是别的 agent，防不了你自己跟丢自己的页面。每次导航后都要显式读一次确认身份。

## Claude in Chrome —— 单 agent 可以，多 agent 会漏

它够得到用户的 Chrome，一个 agent 看一样东西时很方便。
但它**没有任何隔离边界**：`tabs_context_mcp` 返回一个所有并发 agent 共享的扁平标签页组，
把所有人的标签页和 URL 都列出来。省略 `tabId` 会解析到「共享组里的第一个标签页」，
于是三个天真的 agent 全都写到了同一个物理标签页上——三者的抢占次数是 10、0、4，
**那个 0 属于一直在覆盖别人的那个 agent**，不是没被覆盖。

每次调用都显式传 `tabId` 能修掉大部分（12/12、11/12、10/12 干净），
但**这是纯客户端纪律，没有任何东西强制它**——任何一个 agent 的一次疏忽都会落在别人的页面上。
在你开始显式传 id 之前创建的标签页永久脆弱，因为 `tabId` 是个裸整数，没有所有权概念。

它还有一个可复现的自伤 bug，三个 agent 里有两个撞上：
**关掉自己的一个标签页，可能会把你整个会话的标签页组跟踪拆掉**，
让你其余的标签页变成永远关不掉的孤儿。跑完之后留下的那些标签页就是从这来的。

**本机浏览器动作默认用 OpenCLI；只有用户明确点名时才用它。**

## 沙箱浏览器（运行环境自带的那个）

本机一切浏览器动作默认走 OpenCLI（`opencli browser <描述性会话名>`，dedicated 窗口，结束后 `close`）。
沙箱浏览器，包括 agent-browser、Playwright、Chrome for Testing 和 headless，
不再是可选项；只有用户明确点名时才用。

**需要登录态的一切都不能用它。** 它是一个干净的独立实例，没有用户的 cookie 和会话，
所以所有要登录的目标要么直接跳登录页，要么以匿名身份返回
**看起来正常但内容不同**的结果——配额更低、字段更少、国家库不同。

这种失败会伪装成「这个工具没有这项数据」，而正确的结论其实是「你没登录」。

**判据：这个页面如果用无痕窗口打开，还是不是同一个东西？**
答案是「不是」，就必须走用户的浏览器。

只读公开文本用 `curl` 或公开 API；需要浏览器呈现或操作时用 OpenCLI。

## 一句话选择表

| 任务 | 用什么 |
|---|---|
| 需要用户的登录态 | **OpenCLI** |
| 要能被脚本 / 别的运行时重放 | **OpenCLI** |
| 多个 agent 并行操作页面 | **OpenCLI** + 每个 agent 一个显式会话名 |
| 测试/验收自己的网站、E2E、截图、支付测试 | **OpenCLI**（dedicated 窗口 + 描述性会话名，结束 `close`） |
| 只是读一段公开文本 | `curl` / 公开 API，**不要开浏览器** |
