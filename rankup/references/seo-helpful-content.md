### 更新与实际影响：事实和推断分开

- 【官方】2024 年 3 月有用内容系统演进并进入核心排名系统；同月公布 scaled content abuse、expired domain abuse、site reputation abuse 政策。规模化滥用看目的和用户价值，不限于 AI，也包括人工或混合制作。[排名系统说明](https://developers.google.com/search/docs/appearance/ranking-systems-guide#helpful-content) / [2024-03-05 公告][M]
- 【官方】AI 本身不被一律禁止，也不自动获得排名优势；为操纵排名而自动生成内容违反政策；署名和披露应在读者合理期待时提供。现行 G 还明确要求发布前人工核事实与可信度，覆盖正文及元数据。[AI 博客/FAQ][A] / [生成式 AI 指南][G]
- 【官方】2026-09-24 Spam Update 全球、全语言推出，预计最多两周；截至核实时该事件页未标完成，也没有列出“专打 AI / programmatic SEO”的目标。[官方事件页](https://status.search.google.com/incidents/XhUDXP7A67iHCD2kmbVu)
- 【业内观察】2025-08-29 Roundtable 汇总 Glenn Gabe 的初步案例：程序化页、doorway、同主题改写页疑似大跌；观察者同时说还需深入分析。属于时间相关案例，不是所有程序化站被惩罚的证据。[报道](https://www.seroundtable.com/google-august-2025-spam-update-impact-40018.html)
- 【业内观察】SISTRIX 的 2025-08-29 报告（2026-03-25 修改）展示 goong.com 先前 27,443 个排名 URL 及可见度下降；同时承认总体影响较低、迁移/被黑等干扰使全面输家名单难以建立，不能据此推导 AI 惩罚率。[数据报告](https://www.sistrix.com/blog/august-2025-spam-update-data-analysis-and-background/)
- 【业内观察】2025-07-22 核心更新汇总记录部分历史 HCU 受影响站恢复、也有站下降；未隔离 AI 制作方式，不能当“AI 站一律下降”的数据。[报道](https://searchengineland.com/data-providers-google-june-2025-core-update-was-a-big-update-459226)
- 【业内观察】2026-10-01 Roundtable 报道 9 月更新中的跌幅及 Reddit AI 翻译页在部分国家回升；波动方向不一致，制作方式并非充分解释。[报道](https://www.seroundtable.com/google-september-2026-spam-update-two-42209.html)
- 【业内推断/未核实】“本次 Spam Update 专门打击批量 AI”“深圳 SEO 大会证实了算法目标”均未取得可核查的一手证据。文档加强可支持质量整改方向，不能证明同期算法新加了 AI 检测规则。[官方已公布范围](https://status.search.google.com/incidents/XhUDXP7A67iHCD2kmbVu)

## 二、E-E-A-T 现在的口径

【官方】Trust 最重要；E-E-A-T 不是一个独立排名因子，不要求每篇同时证明全部 E/E/A。评分员反馈用于评价系统，不直接给页面排名。[H][H]

| 维度 | 官方口径 | 内部可核对证据 |
|---|---|---|
| Trust | 准确、诚实、可靠；其他维度支持信任 [Q §3.4，p26][Q] | 关键声明逐条对应来源/实际结果；责任主体、联系入口可达；收费、限制与真实流程一致 |
| Experience | 与主题相关的一手经历 [Q §3.4][Q] | 原始操作截图、输入/输出、体验日期；游戏攻略有真实玩法记录；不能把 AI 样图称实测照片 |
| Expertise | 完成该主题所需知识和技能 [Q §3.4][Q] | 方法/公式/代码与参考结果对应；涉及专业建议时核对真实资格、审阅者及审阅范围 |
| Authoritativeness | 网站或作者是否是该主题公认的可靠来源 [Q §3.4][Q] | 可打开的独立报道、引用、维护记录；自称专家、买链接或 DR 分数不当作专家证明 |
| YMYL | 可能显著影响健康、财务、安全或社会福祉的主题更重视强 E-E-A-T [H][H] | 标出具体风险声明；逐条核对权威来源、适用地区与日期；高风险建议有真实专业审阅 |

【官方】YMYL 的安全个人经历分享与专业建议应区分；一手经历不自动授权医疗/投资建议。外部独立信誉要核查；小站没有信誉资料不等于负面信誉，极度负面信誉可支持 Lowest。[Q §3.3、§3.4.1、§4.5.2，p22–28、36][Q]

## 三、主内容四属性与可检查判据

【官方】主内容包括功能与交互；工具和游戏的投入可以体现在背后系统，不能只按正文长短判断。信息页要准确，YMYL 应高度准确且符合已确立专家共识。[H / Main content][H] / [Q §3.2，p21][Q]

下表定义来自 H；数量、证据和操作为【内部闸门】，用于后续 review，本任务不执行网站审查。

| 属性 | 官方定义 | 工具 / 游戏 | 多语言 | AI 产品 / 程序化页 |
|---|---|---|---|---|
| Effort | 人工用于内容或系统的投入；无人工监督/策展的 feed 或批量 AI 产文属于极少或无投入；引用不代替原创投入 [H][H] | 能指到实际维护的功能源码、玩法/输入输出记录、最近一次人工修订；工具可完成任务，游戏能进入真实一局 | 每个 locale 有真实审校者/团队、日期及修订实例；翻译服务的系统投入与批量复制译文分开检查 | 生成流程里找人工复核/策展记录及被改/弃的实例；每个索引页能关联真实数据或功能；单纯生成次数不算投入 |
| Originality | 他站没有的独特信息或视角 [H][H] | 至少一项可指出位置的独有功能、原始演示、攻略或分析；嵌入游戏有有用的玩法/策展依据 | 核对地区输入、单位、当地规则/资源或自然表达；真正好用的翻译可有价值，不强行虚构本地事实 | 去掉标题/实体名后比较主内容；每个索引页有实体特有的数据/结果/选择依据；引用源旁能指出本站新增了什么 |
| Talent or skill | 足以带来满意体验的技能；并非全需专门资格 [H][H] | 打开页面完成主任务；检查结果可用、玩法说明与实际一致、关键按钮不成空壳 | 用真实目标语言输入并完成任务；核对语序、RTL、文本截断及地区格式，不只查 hreflang | 样例能按公开条件复现；输出达到明示用途；模板不出现错实体、字段空缺或互相矛盾的段落 |
| Accuracy | 信息事实准确；YMYL 高度准确且符合专家共识 [H][H] | 公式、单位、规则、版本与来源对应；保存普通/边缘输入的预期与实际结果 | 各 locale 数值与适用地区一致；日期、法规、货币与资料版本可核对 | 每条数字/“最好”/测试声明有来源、日期、方法；AI 事实核查覆盖正文、title、description、结构化数据及 alt [G][G] |

【内部检查方法】按真实内容目录替换路径后只读检索：`rg -n 'author|reviewer|dateModified|source|method|locale' src content`；再打开页面核对显示值、证据链接与主功能。命中字段只证明字段存在；没有命中也不能直接证明没有人工投入。

## 五、「Who / How / Why」页面披露规范

【官方】在读者合理期待时提供准确作者信息、制作方法和自动化使用背景；目标应是帮助来访者。把 AI 列为作者不一定能清楚表达其实际角色。[H][H] / [AI FAQ][A]

以下是【内部写法要求】，占位字段只能用真实资料填写，缺失就标未知；不能发布虚构姓名、履历、审阅、样本或测试。

| 位置 | 写法要求 | 可采用的正面表达 |
|---|---|---|
| 作者页 / 署名 | 标实际个人、稳定别名或负责团队；职责、相关作品和真实经历可核查；审阅者与作者角色分开 | “本页由〔真实团队〕维护，负责〔实际工作〕。相关作品：〔链接〕。” |
| About | 真实运营主体、站点服务的用户与范围、联系/纠错方式；产品页可由公司承担内容责任 | “我们为〔受众〕提供〔现有功能〕。内容与工具由〔主体〕维护，问题可通过〔真实入口〕反馈。” |
| 方法说明 | 输入、数据来源/版本、计算或选择方法、实际样本数量、核对时间、限制；自测与第三方事实分开 | “结果依据〔来源/公式〕，适用〔条件〕。本次核对覆盖〔实际范围〕，记录见〔证据〕。” |
| AI 使用披露 | 谁负责；AI 做了什么；真实人工编辑/复核范围；为什么有帮助；实时生成与编辑发布内容分开 | “本页使用〔工具〕辅助〔实际步骤〕；〔真实团队〕核对了〔真实范围〕，并完成〔实际修订〕。” |
| AI 产品输出说明 | 就近说明输入如何生成输出、用途和能力边界；无人工复核时如实写，不冒称验证 | “此结果由模型根据你的输入生成。适用于〔实际用途〕；生成方式与限制见〔方法页〕。” |
| Why | 明确受众可完成的任务与实际收益；用页面功能/数据证明，不用套话 | “这个页面帮助〔用户〕在〔场景〕完成〔任务〕，提供〔实际增量〕。” |

【内部】披露存在不抵消红线；给低质生成内容补作者页、来源或 AI 标签仍不能证明原创投入。该原则对应 H 的 Effort 与 Q 的低增量 MC 条款。[H][H] / [Q §4.6.6][Q]

## 六、站点级自检表和单页级自检表

### 站点级自检表

【内部】每季度或 Google Spam/Core Update 后复查；先列全体可索引 URL、模板、语言和数据源。全量做元数据/空字段/重复内容检索；人工看首页、About、方法页及每个“模板 × locale”至少 3 页（不足 3 页全看，含最新/高流量/随机页）。抽样结果只代表所查范围，不能宣称每页已通过。

评分通则：**0**＝缺失/未知/错误；**1**＝部分覆盖或证据不完整；**2**＝满足判据且所查范围证据可追溯。确实不适用须写理由及范围，计 2；不能以“不知道”记不适用。每项填 `分数｜URL/文件证据｜日期｜范围`。

| 项 | 0 / 1 / 2 的对应判据 |
|---|---|
| S1 受众与焦点 | 无目的 / 部分页面脱离受众 / 全部模板能说明真实受众和任务 |
| S2 身份与责任 | 无主体或假资料 / 主体明确但入口/职责不全 / 作者或实体、About、联系与职责一致 |
| S3 人工投入 | 无记录 / 有记录但缺模板或语言 / 所有生成路径有维护、策展/复核及实际修订证据 |
| S4 独特增量 | 只换词或搬运 / 部分页增量可指认 / 所查页均有数据、功能、分析或使用价值 |
| S5 主功能技能 | 不能完成任务 / 部分模板或语言失败 / 所查主任务均完成并留结果 |
| S6 准确与 YMYL | 关键错误或未知 / 部分来源/审阅不全 / 关键声明与地区版本可核，高风险专业审阅真实 |
| S7 Who/How/AI 披露 | 隐瞒/伪造 / 部分页面欠缺 / 读者所需身份、方法、AI 角色均准确公开 |
| S8 语言与模板质量 | 机械翻译/空字段 / 局部审校或增量 / 所查 locale 与实体页均能满足其受众 |
| S9 体验与信誉 | 遮蔽 MC/可信严重负面问题未处理 / 核查或体验覆盖不足 / 主任务可达，独立信誉检索有记录、已知问题有处理 |
| S10 索引与更新治理 | 量产薄页或假新鲜 / 已分诊但未处理 / 不合格页已停止索引扩张并处置，日期有实质依据 |

通过：**≥18/20、无红线、S2/S3/S5/S6/S7 均为 2、其余不得为 0**。理由：只允许最多两项非关键项待完善，身份、投入、可用性、事实和披露不可用总分补偿。此分数不是 Google 指标，不预测排名，也不证明全站不存在遗漏。

### 单页级自检表

【内部】每个新增/实质改动的可索引页逐项核，不用代表页替代；共用模板证据可复用，实体数据、事实及语言内容仍须逐页核。

| 项 | 0 / 1 / 2 的对应判据 |
|---|---|
| P1 目的与承诺 | 答案/功能不存在 / 承诺部分满足 / 标题承诺和真实主任务一致 |
| P2 责任与信任 | 无责任/造假 / 信息不完整 / 实际作者或实体可追溯，来源与关系诚实 |
| P3 Effort | 无投入证据 / 系统或人工记录不全 / 有具体维护/编辑/策展依据，AI 事实经真实复核 |
| P4 Originality | 无价值复制/换词 / 增量有限且不清楚 / 明确指认本站功能/数据/经验或使用增量 |
| P5 Talent/skill | 主任务失败 / 局部步骤失败 / 完整完成主任务，输出可用，说明与实际一致 |
| P6 Accuracy | 关键错误/来源未知 / 部分核对 / 关键事实、输入输出、适用版本核对完成；YMYL 有真实专业审阅 |
| P7 Who/How/Why | 缺失或隐瞒 / 仅笼统标签 / 身份、方法、AI 使用角色与目的符合实际 |
| P8 页面体验与本地适配 | MC 不可用/误导 / 有未解决干扰或语言缺陷 / MC 可达，目标语言/单位/地区适配，日期可信 |

通过：**≥15/16、无红线、P1/P2/P3/P5/P6/P7 均为 2、其他项不得为 0**。最多允许一个非关键项部分满足；未过就记具体原因和证据，不能靠其他项补回造假或错误。站点通过不能代替单页通过，单页通过不能代替站点治理。

## 七、不合格时的整改动作优先级

以下顺序为【内部整改流程】，只针对已证实不合格内容，不以流量下降直接触发全站删除。

1. **先处置薄页与停止扩张**：列出不合格 URL 与理由；重复页合并到能完成目的的页面；无独立价值且无法修复的页删除；有保留用途但当前不达标的页先 `noindex`。恢复索引前重过单页表。S 对规模化滥用明确要求排除出 Search。[政策](https://developers.google.com/search/docs/essentials/spam-policies#scaled-content-abuse)
2. **再补真实增量与准确性**：优先修主功能、数据错误和高风险声明；补原始记录、可用工具、实际攻略、可靠数据或目标地区使用价值。能修好的原页优先改善，不能把换词/引用/长正文当增量。[H][H] / [Q §3.2][Q]
3. **再补准确披露**：据真实完成的工作写责任主体、方法、来源、审阅范围和 AI 角色；披露缺失也要在恢复索引/发布前清零，不能用虚构履历补信任。[H][H] / [A][A]
4. **记录并复查**：保存逐 URL 判据、改动与检查日期；重新过两层表，排名/流量恢复单独观察，完成整改不能报告为已经恢复排名。[核心更新指导](https://developers.google.com/search/docs/appearance/core-updates)

【官方】没有偏好字数；改日期或为“新鲜”大量增删无助于该目标。核心更新指导也要求避免仓促修补，删除应谨慎、在无法挽救内容时考虑；不能将本节当成遇到下降就大批删页的 Google 指令。[H][H] / [核心更新指导](https://developers.google.com/search/docs/appearance/core-updates)
