## 四、差评与「许愿句式」：用户原话就是页面标题

【经验】—— `金智` / `黄楚标` / `楓之随刃` / `日出东方`，`bounty/fd0wrgx7fh`

**差评是唯一由用户掏钱之后给出的反馈**，可信度远高于任何免费调研。
功能列表告诉你「他们做了什么」，差评告诉你「他们做了但没做好的」——后者才是机会。

### 4.1 差评矿脉分布

| 平台类型 | 适合研究什么 |
|---|---|
| SaaS 点评站（B2B 向） | 企业级 SaaS 的采购期望与落差 |
| 应用商店（移动端两家） | 付费意愿最明确的一批用户 |
| 浏览器扩展商店 | Micro SaaS / 工具站的直接对标 |
| 电商与建站平台的应用市场 | 垂直行业 SaaS 的现成需求清单 |
| 开源插件生态 | 技术用户的痛点，往往是「能用但难用」 |
| 泛社区与聊天社群 | 非结构化的真实吐槽，出现频次比单条内容重要 |

### 4.2 高价值差评关键句（直接当搜索/过滤词用）

```
Doesn't work with...      Please add...        Too expensive
Slow                      Stopped working      No longer works
Privacy                   Wish it could...     Need bulk...
```

**其中最值钱的一句是「I love this extension, but...」**——
前半句证明需求真实且用户已经投入，后半句就是切入点。

### 4.3 社区「许愿句式」

在搜索引擎里限定站点搜这些句式，命中的都是用户自己写下来的需求原话：

```
site:<社区域名> "is there a tool that" <领域词>
site:<社区域名> "I wish there was" <领域词>
site:<社区域名> "does anyone know a" <领域词>
site:<社区域名> "how do people make" <领域词>
```

延伸的**迁移类句式**同样高价值（这类用户需求已经明确，只是在换供应商）：
`alternative`、`replacement`、`migrate`、`too expensive`。

### 4.4 扩展商店的「已验证市场 + 差执行」信号

【经验】—— `金智`，`bounty/fd0wrgx7fh`。做 Micro SaaS / 工具站最值得挖的一条线。

**筛选形状：用户量很大，但评分不高。**

```
用户数 100K+ / 500K+ / 1M+   ×   评分 3.5 ~ 4.3
```

这个组合的含义是 **Validated Market + Bad Execution**——市场已经存在，产品执行不好。
然后去读评论区的那几句关键句（见 4.2）。

### 4.5 退款理由与「产品下线」

- **【实测】退款理由是最贵的信号**：它是用户掏钱之后主动要求拿回钱，
  给出的理由通常极其具体（有答主的一个退款理由是「找不到联系方式」）。
  样本量小不影响价值，因为它没有任何免费调研的表演成分。（`日出东方`）
- **【经验】关注大产品宣布关停**：几千万存量用户 + 官方迁移体验差
  = **数据迁移成为强时效刚需**。有案例是一个极简的导出扩展吃到近十万用户。
  监控形状：产品下线公告、扩展商店的下架/停更列表。（`清仔`）

### 4.6 拿到差评之后怎么读：三条纪律

【经验】—— 独立开发者出海经验分享（外部经验帖，未经本库实测）

4.1 回答的是"去哪儿挖差评"，这三条回答"挖到了怎么读"，每一条都会改变计数结果：

1. **不看星级看任务。** 有价值的不是他给了几星，是**他原本想完成什么、产品在哪一步没接住他**。
   读不出这两样的差评只是情绪，不进证据库——这与 4.2 那批关键句是同一个用法：
   那些句子之所以值钱，正因为它们后面跟着一个具体的任务。
2. **一条差评只是一个人的一次经历。** 判断偶发还是普遍，必须在别处找到同形状的抱怨，
   计数纪律见 [`../playbooks/selection.md`](../playbooks/selection.md) 闸门 2。
3. **差评会过期，必须亲自试用竞品复核。** 评论区里那条吐槽可能已经被修掉了，也可能官方早给了
   变通办法，而差评永远留在那里，日期还不一定显眼。**没有亲手走一遍竞品的对应流程，
   就不能把这条吐槽当成今天还存在的缺口**——这是差评矿最便宜、也最常被跳过的一步，
   跳过的代价是整个方向建立在一个已经被填上的坑上。

## 五、中文平台当探测器：国内卷得早，验证过的搬到英文市场

【实测】—— `袁锐钦` / `楓之随刃` / `Rhythmus`，`bounty/fd0wrgx7fh`

核心假设：**国内内容与交易平台的竞争密度高于英文市场，
在国内已经被验证过的需求，搬到英文市场往往还是一地垃圾站。**

| 平台形态 | 看什么 | 判据 |
|---|---|---|
| 内容平台的**搜索下拉联想** | 用户高频搜索的原话 | 联想词本身就是关键词 |
| 内容平台的**笔记数 vs 赞藏数** | 供给 vs 需求 | **内容少 + 赞藏高 = 最优机会**；评论区高频问「用什么工具」= 工具站需求 |
| 短视频平台**头部视频播放量** | 需求有没有流量 | 10w+ 且多条 = 有流量；评论区「求链接」「在哪买」= 变现信号；**有直播间在卖 = 商业闭环已跑通** |
| 二手交易平台（**最硬**） | 「想要」数 vs 商品数 | **想要多、商品少 = 供不应求**；有人卖 + 有成交 = 有人真掏钱。服务类需求（「XX 代做 5 元/张」）直接对应工具站机会 |
| **招聘 JD** 反推 | 多少公司在招同一类岗位 | 多家同时招 = 方向起量；**JD 里的高频词 = 行业正在用人力解决的问题** |
| 视频平台**评论区**（英文侧确认） | 中文验证过的词翻译后搜头部视频 | 有播放 = 英文有需求；评论里的「Is there a tool for...」= 需求在、供给缺 |

### 一个纯主观但很好用的信号：「就这？」

【经验】—— `Rhythmus`，`bounty/fd0wrgx7fh`

在推荐流平台上看到有人晒自己做的小工具，笔记流量大、点赞多、评论里感兴趣的人多，
**而你自己的第一反应是「就这？不就是 XXX 吗，我轻轻松松也能做」**——
那这个工具解决的问题大概率是个优质需求。

判据补充：骂的人少、说「求你别再做这个了」的少；说「这也太简单了吧」的人点进主页
看多半是写代码/重度用 AI 的人（**同行觉得简单 ≠ 用户觉得简单**）。

这个信号一次给齐四样东西：**需求具体、人群画像清晰、能推导定价、社媒营销策略也现成**。

## 六、延展法与「持续涌现新词的平台」

### 6.1 延展法：从一个已验证的原点向外扩

【实测】—— `李大山`，`bounty/fd0wrgx7fh`

和「词找站、站找词」共通，但方向不同：**先锁定一个已经被市场验证过的单点需求，
再沿着业务流程、场景、细分维度向外扩散**，梳理整条链路上现存的痛点。

原帖案例（AI 图像方向）：观察到「AI 职业头像」「AI 头发生成」这类工具已经拿到真实流量
→ 证明「生成人体局部图像」这个市场成立 → 以此为原点向外延展到人体其他部位
→ 衍生出一整串关键词与产品方向 → 顺着这条线找到了一个月访问量约 20 万的站。

**操作形状**：找到原点 → 沿场景/流程/细分维度做横向与纵向延展 → 批量得到衍生关键词。
任何行业都能套用。

### 6.2 研究任务的前一步和后一步

【经验】—— `Zhou.`，`bounty/fd0wrgx7fh`

一个工具完成了核心任务，**用户在这之前还要准备什么？之后还要导出、检查、分享什么？**
这些小环节往往竞争小得多，而用户已经在做了。

### 6.3 去持续涌现新词的平台捡新词

【经验】—— `清仔` / `峻菁`，`bounty/fd0wrgx7fh`

**新游戏就是新词，新词就是新需求。** 新品类持续上新的平台（游戏数据库、
游戏聚合站、独立游戏发布站、模型与新产品发布渠道）天然不断产出没有老站霸占的词，
**新手很适合从这里拿第一次正反馈。**

与之配套的验证动作（`峻菁`）：拿词去 SERP 首页看三件事——

1. 有没有站**用这个词做主域名**；
2. 有没有站**用这个词做内页**；
3. 这个词的 **KD** 是多少。

再叠一层时间维度：用自己积累的词库（哪怕是一张表格）看**某个词在过去 1–2 个月里，
搜索结果数量是不是在匀速递增**——递增说明这是个在起量的词，不是一次性热点。

## 七、自有站就是一座矿：GSC × 分析后台交叉

【实测】—— `日出东方` / `Dawn`，`bounty/fd0wrgx7fh`

**这一节性价比最高**：需求已经被确认存在（用户真的搜进来了），你只是在浪费它。

### 7.1 高曝光 + 高点击 + 低停留 = 已确认但没被满足的需求

只看流量是浪费。把 Search Console 的「搜索词 → 落地页」和分析后台的
「停留时长 + 跳出率」拼起来看，找 **高曝光 + 高点击 + 低停留** 的组合：

> 这类词含义很明确：用户带着明确期待搜进来了，我没给到他要的东西。
> 不是需求不够，是需求已经被确认存在，而我正在浪费它。

实操：导 28 天「查询–页面」数据 → 导页面停留时长 → 按落地页 join
→ 筛 **点击 > 10 且停留 < 30 秒** → 逐个看这些搜索词到底在问什么。

原作者用这张表挖出过一个工具，现在每周两百多人在用免费功能，
并且明说「这张表里肯定还躺着好几个没做的」。

### 7.2 直接让 AI 过一遍 GSC 全部搜索词

找哪些需求没被满足，然后深入调研并实现。这条和 7.1 是同一个矿的粗筛与精筛。（`Dawn`）

### 7.3 竞品的「付费墙位置」逆向法

【经验】—— `日出东方`，`bounty/fd0wrgx7fh`

竞品数据库里记支付平台、定价、免费额度、Upsell 都是表面。
**真正的信息是：竞品把付费墙放在哪一步。**
付费墙的位置是竞品用真金白银试出来的「用户愿意掏钱的那个瞬间」——
**他们已经替你做完了 A/B 测试，答案就明晃晃写在页面上。**

| 付费墙位置 | 说明什么值钱 |
|---|---|
| 输入信息后立刻收 | 「生成结果」这个动作本身值钱 |
| 给了摘要之后才收 | 「完整性」值钱 |
| 第二次访问才收 | 「持续性」值钱 |
| 只在某个特定问题上收 | **那个问题最痛** |

反向自查：如果你的免费功能有人用、却一个都不付钱，
很可能是**免费部分给多了，用户在走到付费墙之前就已经满足了**。
