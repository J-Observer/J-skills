# 0→1 的规划与迭代纪律

来源：`new.web.cafe/ask/bounty/fpswv8z126`（「你觉得从 0 到 1，哪三件事最重要」，
131 位投资人、19 条回答）。收录规则与证据等级说明见 [`INDEX.md`](INDEX.md)。

这一章不讲怎么找需求（那在 [`demand-discovery.md`](demand-discovery.md)），
讲的是**立项之后到跑通闭环之间，怎么排优先级、怎么判断进度、什么时候止损**。

---

## 一、先把「1」定义死，否则永远不知道到了没有

【经验】—— 多位作者，`bounty/fpswv8z126`

19 条回答里分歧最大的就是「1」指什么。**定义不同，优先级完全不同**，所以这一步必须先做。
帖里出现过的三档（`小林老师` 的分层最清晰）：

| 「1」的定义 | 达成路径 | 适合谁 |
|---|---|---|
| 赚到第一笔美金 | 选热点模型词/新词/游戏站，用最短时间最小投入把「上线 → 收录 → 付费外链 → 接支付 → 运营」完整走一遍 | 完全没跑通过流程的人 |
| 隔三差五出单 | 做很垂直的站，对标已经在赚钱但规模很小的站（月访问 100k 以内，多半是个人或小团队） | 已经跑通过一次流程 |
| 一个站稳定出单 | 需要前面大量试错的积累 | 已经有多次出单经验 |

**这个定义要写进 `<project>/.rankup/roadmap.md` 的阶段目标，并同时写放弃条件。**
「1」没定义就开工，等于把「什么时候该停」的判断留给情绪。

`程序员卡诺` 给了一个更狠的练习目标：**「我能否在一到两周内赚到 0.01 美元？」**
目的不是这一分钱，是逼你把所有宏大方案放一边，用最简单最快的方案跑完整条链路——
**跑起来之后你会发现一堆之前根本不知道其存在的东西**，那些是复盘不出来的。

## 二、三道关，有顺序

【经验】—— `Niko`，`bounty/fpswv8z126`（当轮第二高分）

```
找对任务  →  跑通付费  →  跑通获客
   ↓            ↓            ↓
有没有       有没有      能不能长期
产品价值     商业价值      经营
```

**第一关：选对需求，问的不是「我要做什么功能」，是「谁在什么场景下，
有一件什么事情必须完成」。** 任务越具体，后面的产品、文案、定价、渠道越容易确定。
「AI 图片」「AI 视频」这种泛需求不是好的 0→1 机会。

**第二关：只做一个最小但完整的可售卖切片**——用户进来 → 完成任务 → 看到结果 → 愿意掏钱。
`Zhou.` 补了一个关键区分：**「最小」是少做功能，「完整」是用户真的能用**，闭环不能残缺。
7–14 天做出可用版本即可。

**第三关：找到一条可重复的用户供给路径。** 第一单不是终点，问题是「怎么持续找到第二个、
第一百个同类用户」。渠道是 SEO 还是 Ads 还是社区都不重要，**必须能重复、能衡量、能持续优化**。

## 三、什么是虚荣指标，什么才是验证信号

【实测】—— `日出东方`，`bounty/fpswv8z126`。这是整帖里最贵的一条，因为它附了失败数据。

> 项目 3：流量 897 → 注册 86 → 免费使用次数 238 → **支付 0**。
> 前三个数字都是虚荣指标。它们证明用户愿意来，不证明用户愿意掏钱。

**真正的验证信号，四个条件同时成立**：

1. **一批人**（不是一单）；
2. **没有优惠**；
3. **没有你亲自解释**；
4. **自然付款，且不退**。

原作者对自己最狠的一句复盘：**「第一单进来我就 all in 加速，现在回头看，一单不是验证，
四单退两单更不是。我把 0 当成了 1，然后在 0 的地基上加速了两个月。」**

**判据落地**：这个信号出来之前——**不开新站、不重构、不加速**。
写进 `.rankup/roadmap.md` 当阶段闸门。

另一条同源的真伪需求判据（同帖，`日出东方`）：
**用户会不会自己回来第二次。** 不回来就是伪需求，不管你多喜欢它。

## 四、漏斗不是拿来看的，是拿来定位问题的

【实测】—— `日出东方`，`bounty/fpswv8z126`

「238 个用完免费功能的人卡在哪一步」只有三种答案，**对应三种完全不同的修法**：

| 现象 | 问题类型 | 严重程度 |
|---|---|---|
| 没看到付费入口 | UI 问题 | 最好修 |
| 看到了但价格劝退 | 定价问题 | 可测试 |
| **免费部分已经够用了** | **产品结构问题** | **最致命** |

不定位就只能凭感觉改。原作者凭感觉改的代价：支付重写、接 Stripe、数据库搬家、
定价体系推倒重来，三周多，**付费仍然是 0**。

## 五、打磨 > 重构（这条是本章最反直觉的一条）

【经验】—— `日出东方`，`bounty/fpswv8z126`

> 重构有快感：宏大、清晰、做完像干了件大事。
> 打磨没快感：改文案、调措辞、追用户卡点，琐碎、慢、看不见成绩。
> 焦虑的时候本能选重构，因为它能马上缓解「我没在推进」的不安。
> **但 0→1 真正有效的，几乎全是打磨。**

同一个坑的另一个形态（`王焱`，同帖）：**别在技术活上恋战。**
自动化投放外链这类活的危险在于**它做起来特别像在干活**——有步骤、有清单、每天有进度，
**但它不回答 0→1 阶段唯一的真问题：这个站的需求到底存不存在。**
技术问题这个阶段够用就行，别用它逃避真正难的事。

> 对我们的意义：这条直接约束 Agent 的行为倾向。接到「优化一下这个站」这类模糊指令时，
> 默认动作应该是**打磨转化链路**，不是重构架构或补自动化工具。
> 要动架构，必须先给出「架构是当前瓶颈」的证据。

## 六、先手工跑通，再自动化；扩了亏损立刻收缩

【经验】—— `楓之随刃`，`bounty/fpswv8z126`

```
弄清需求  →  自己手动跑通整个上线流程  →  才考虑工具/雇人扩展
```

原作者的教训：开发还没搞完就想着做自动化，需求都没验证过——**砍柴砍一半去修路**。
很多需求一张图就能验证。

扩展阶段的硬判据：**扩了之后从盈利变成亏损，立刻收缩；只有还能赚钱，才继续扩大。**

## 七、完成比完美重要，但不是「随便做」

【经验】—— `阿鲁巴`（当轮最高分）与 `Angler`，`bounty/fpswv8z126`

【实测】已有相关且健康的站点时，可先用一个能完成任务的内页试新需求：观察实际搜索查询、使用和自发分享，再决定是否投入独立站；独立站仍需核对品牌与素材权属（Alan，[复盘](https://new.web.cafe/topic/vsodvlomjz)）。这是新需求试水，不适用于下滑老站的救站判断。

【实测】传播型产品的结果要能清楚展示用户特征、便于一键分享；发布后看实际分享和回访，再决定是否加大推广，不能把分享按钮本身当作传播成效（小张，[复盘](https://new.web.cafe/topic/4k6f2747an)；Alan，[复盘](https://new.web.cafe/topic/vsodvlomjz)）。

【实测】参考竞品需求或玩法后，代码、界面、素材和品牌必须独立实现；上线前核对是否直接复制原页面资源及使用他人品牌，已有直接复制引发投诉、迁移和停止运营的案例（LoneRanger，[复盘](https://new.web.cafe/topic/n8imwfu7xv)；Alan，[复盘](https://new.web.cafe/topic/vsodvlomjz)）。

- **不上线的产品等于不存在。**「准备综合征」——等这个功能做好、等那个 UI 顺眼——是最常见的
  拖延形态。原作者第一个月直接上了两个站，「粗糙得一塌糊涂，但它们是活的」。
- **「想清楚了再干」要反过来：干清楚了再想。** 停留在脑子里的时候，所有判断都是幻觉。
- **但这不等于随便做。**`Angler` 给了程度上的校准：功能可以只做 80% 先上线占坑，
  **产品场景和思路一定要理顺**——AI 给的方案经不起推敲，前期自己琢磨一遍，
  实在不明白再让 AI 出方案占坑。

  与本 Skill 已有的硬规则不冲突但要一起看：
  [`webcafe-experiences.md`](webcafe-experiences.md) 第四条——
  **网站没做完可以上线，但页面 SEO 文案必须先完善才能给爬虫爬**，
  否则爬虫按空页面打的分不会当场扣完就算了。

## 八、上线执行清单（从业者取向，含与本 Skill 的冲突裁定）

【经验】—— `Angler`，`bounty/fpswv8z126`，一条完整的新站执行清单。
**其中数条与本 Skill 的默认栈冲突，逐条给出我们的裁定。**

| 环节 | 帖里的做法 | 我们的裁定 |
|---|---|---|
| 落地页结构 | hero + 功能表单 → 功能特点 → 用户痛点+解决方案（含对比）→ 场景案例 → 用户证言 → FAQ → CTA | **采纳**。新站没有真实证言时放示例工作流，**不要编造用户评价** |
| 多语言 | 每个语言的关键词都要重新找，直译效果差 | **采纳**，与 [`webcafe-experiences.md`](webcafe-experiences.md) 第三条一致 |
| 域名 | AI 站优先 `.ai` 后缀，其次 `.com`；不要带横杠 | **参考**。属于概率判断，无实测数据 |
| 素材 | 生成图能看出「AI 塑料感」，用户会介意；能自己找图更好 | **采纳** |
| **技术栈** | **「就 vercel，千万别用 cf，cf 免费很强但坑多、架构复杂」** | **不采纳，但记录分歧。** 本 Skill 默认 Cloudflare-first（见 [`../cloudflare-stack.md`](../cloudflare-stack.md)），理由是 SSR/D1/R2/Queues 在同一平面内、部署与验证已脚本化。原作者的顾虑（学习曲线、架构复杂度）对**没有既有脚手架的个人**成立，对我们不成立——我们的脚手架和部署验证流程都已固化。**分歧的真正落点是「有没有现成模板」，不是平台优劣。** |
| 数据库 | Supabase / Neon，不够再迁 | **不采纳**，同上，我们默认 D1；除非项目明确需要 Postgres 能力 |
| 定价 | 前期方案不要多，避免选择困难；成本约为售价的 1/3 | **采纳**为默认起点 |
| 支付 | 多渠道冗余（原帖偏好 Waffo，因其提供 Apple/Google Pay 与微信支付宝） | **采纳「多渠道冗余」这条原则**；具体渠道按项目决定，见 [`../integrations.md`](../integrations.md) |
| 转化点 | 新用户短期优惠、每日登录积分、积分不足提示、导航站折扣码、付费去水印、单张购买——都得有 | **采纳**，细节见 [`conversion.md`](conversion.md) |
| **付费导航站** | **一定要付费上导航站**（taaft、toolify、creati.ai），需求找得用心、产品及格通常很快回本 | **采纳**。免费的推荐 dang.ai、Fazier、Twelve.tools。**注意**：免费导航站要求在 footer 贴徽章，**贴多了像狗皮膏药、降低信任度，要克制** |
| 外链 | 去 toolify 找竞品 → Semrush 采集 → 归类；前期手动每天发 10 个，不追求全自动 | **采纳**。全自动效果不好控制；保持合理外链结构，别一次发太多。工具见 `backlink` Skill |
| 客座文章 | 有预算上一批，约 2000 元就能看到排名提升 | **参考**，无实测对照 |

`袁锐钦`（同帖）补充的一条模板化主张同样值得记：**第一版最好是用模板拼出来的，
不是从零开发**——选词 → 模板 → 部署，做成一条流水线。这与我们默认脚手架的思路一致。

## 九、上线之后：数据驱动的迭代节奏

【经验】—— `袁锐钦` / `日出东方`，`bounty/fpswv8z126`

上线不是结束，是验证开始。每周看 GSC：

【实测】热点站首版上线就分别记录 GSC 的收录、查询、曝光、点击和站内使用或订单；这些状态不能互相替代。先看用户能否完成核心任务，再用反馈、行为记录与地区分布决定下一轮功能和页面（运气选手走得远，[复盘](https://new.web.cafe/topic/6dx0cbme8c)；北海，[复盘](https://new.web.cafe/topic/ckyxmax9i4)；未署名作者，[复盘](https://new.web.cafe/topic/l8n2hjtx6d)）。

- **有排名的词** → 加内容加深，往首页推；
- **没排名的词** → 判断是内容问题还是词选错了。

**数据积累 3 个月，才知道这个站值不值得继续投入。**
用原帖的分段说法：选对需求（方向）和快速上线（速度）只是 0 → 0.1，
**数据迭代（复利）才是 0.1 → 1**。

配套动作：**上线前就把止损线写好**（`Zhou.`，同帖）。有信号就先做深度再做广度，
没信号就停止投入，**留下模板和经验**——这两样是下一个站的起点。

> 落地位置：止损线写进 `.rankup/roadmap.md` 的放弃条件；
> 每轮的判据、结果、下一轮唯一改进写进 `.rankup/iterations.md`。
> **失败轮次同样要写，且必须写清被证伪的假设**——这正是本章所有条目的产生方式。

## 十、心态层（压缩版）

帖子里近半数回答落在心态上。这类内容对 Agent 执行没有直接约束力，只保留会改变动作的部分：

- **在没有正反馈的时候按原计划继续执行**，是 0→1 最难的部分，不是技术或资金
  （`阿鲁巴`）。该加内页加内页，该做外链做外链。
- **试错没有惩罚，这与考试/打工的思维完全相反**（`程序员卡诺`）。用最短时间试一下这条路
  适不适合自己，不行就换方向，在过程中复盘。
- **正确地重复**（`梦梦.Gu`）：每次重复要比上一次有进步——用时更短、多一种新方法、
  数据好一点、多一条经验沉淀，不追求一次到位。
- **别人的成果基于他的认知、条件和运气**（`Angler`）：可以参考，但要想清楚是否适合自己。
  这也是 [`INDEX.md`](INDEX.md) 里「采纳前先问前提条件是否一样」那条规则的出处。
