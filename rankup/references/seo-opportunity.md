# SEO：机会池选型与冷启动

> 渐进式加载：本篇只讲"鱼多人少"机会池框架。

## 三-A、机会池选型与冷启动(“鱼多人少”框架)

> **定位**:本节来自 Fiona 的出海经验分享,用于发现候选和规划冷启动,不是已经被本站数据验证的结论。文章里的“四个月月入万刀”等个人结果没有可复核证据,不得写进项目基线或当作成功率依据。候选方向的验证顺序、裁决与结论落档只见 [entry.md](playbooks/entry.md)；本篇不承担选词与立项门禁。

### 1. 先选池子,再谈技术

【经验】新项目、新产品线或新词族可用【机会池卡】整理候选背景；已有主词后的验证与裁决只见 [entry.md](playbooks/entry.md#3--流水线)。

| 背景 | 记录什么 |
|---|---|
| 鱼(Demand) | GSC 曝光/点击、Suggest 联想、搜索广告、可核验的付款/订阅/评论或榜单收入等来源与日期；讨论热度、单个爆款和竞品自述保留来源及未核实说明 |
| 人(Competition) | 已存 Google 卡与 ChatGPT 推荐记录的指针；竞品内容新增、外链增长、产品/定价成熟度只作经营观察。有人买高价外链只证明有人投入,不证明项目盈利,更不等于我们也该买 |
| 切口(Wedge) | 内容型修饰词、衍生任务、语言/地区、渠道、结果格式、流程与细分用户等候选缺口，引用问法及两路证据；未核实的标假设 |
| 钱(Monetization) | 省时间、帮助业务赚钱/省人力、娱乐或情绪价值、简化复杂流程等价值假设；记录付款人、付费时刻与替代方案，供立项后规划与经营验证 |

### 2. 跟踪高手留下的时间线,不抄结果页

- **外链时间线**:看早期先出现在哪些社区、目录、发布页和内容页,重点是冷启动顺序、目标页与后续结果;最终公开页必须核对 URL、重定向和 `rel`,不能把目录宣传或当前总外链数当历史证据。
- **新增内容**:通过 sitemap、lastmod、站内新页面、博客/工具发布日期持续记录竞品最近押注的词簇。竞品动作只生成候选假设,验证回 [entry.md](playbooks/entry.md)。
- **真实交互**:实际走完落地页 → 输入 → 生成/结果 → 注册 → 价格 → 支付前一步,拆标题、入口、示例、信任信号、等待反馈和付费点。学习其决策与漏斗,不要只让 AI 复制视觉样式。
- **通过鱼找人**:从新词前排、持续盈利产品和高质量分发位反查反复出现的域名/操盘者,建立观察清单;研究其可见动作,不把个人光环或社群宣传当证据。

### 3. 新手默认先“截流”,能造势的人再造势

- **截流**:承接已经存在、意图明确的搜索需求。用户已经知道要什么时,页面负责更快给出可用结果和顺畅付费路径;这是新站拿首批真实反馈的默认策略。
- **造势**:市场尚无搜索词时,依赖社媒、内容、红人和持续叙事创造需求。只有已有分发能力、内容产能和更长验证预算时才选。
- **热点不要只追第一层词**:沿“事件/模型 → 具体用途 → 衍生任务 → 地区/小语种 → 结果格式”展开候选词,逐层验需求与竞争。小语种晚爆发只是待验证假设,不能凭时间差直接建站。
- **模型词/平台词加风险门禁**:核对商标、冒充官方、模型/API 授权、内容安全、供应商价格与下线风险;能截到流量不代表能长期经营。

### 4. MVP 的目标是拿证据,不是批量制造薄站

- 页面、功能和后台流程可以从最小版本开始;人工处理只在交付真实、时效可控且不欺骗用户时使用。先定义页面唯一要验证的需求和付款理由。
- 从第一天记录 `landing → input → generation success → result action → signup → pricing → checkout` 漏斗。精准流量的价值要用激活、完成、留存或付款证明,不能把访问量和停留时长本身当成功。
- 赠送积分用于让目标用户完成足够次数的真实试用;进度动画、示例和明确状态用于降低等待焦虑。**不要为了“增加停留”故意放慢生成**,速度、成功率和感知等待要分别测。
- 每个版本只改少量变量,记录“保留什么、删掉什么、下一站复用什么”。复用基础设施可以,复制薄内容、相同页面和未经验证的词矩阵不可以。

### 5. 用连续小实验提高胜率,不用“大数定理”安慰盲目铺站

项目成功概率不独立、也不会长期固定;同一错误选词复制十次仍是十次同源失败。【经验】立项后的经营实验记录以下项目，关键词与立项裁决仍只见 [entry.md](playbooks/entry.md#4--判读):

- 固定的时间/现金/外链预算上限;
- 观察窗口与实际样本及局限;
- 本轮要验证的经营假设、观察结果与调整理由;
- 失败后必须更新的假设与下一轮唯一改进。

只有上一轮产生了可迁移学习,增加样本量才有意义。“多上站”应理解为**更快完成多个有止损的小实验**,不是同时养一批没有需求证据的站。

### 6.【机会池卡】模板

```md
候选池/主词 / 国家与语言 / 用户任务:
候选背景: 需求来源与日期 / 竞品经营观察 / 缺口假设 / 付款人与价值假设
入口卡: 路径（验证与裁决按 entry.md）
GT 卡: 入口卡中的证据指针（测量按 trends.md，默认 gpts 基线）
三清单: 竞对 / 关键词与长尾问法 / 页面清单路径（按 seo-geo.md）
逐问法 Google 卡: 路径 / 覆盖与缺项（按 seo-serp.md）
两路结论: 引用入口卡 / 路线与状态 / 缺项和下一步
页面规划: keywords.md 或 Brief 指针（按 stage-2-positioning.md 2.3）
高手时间线: 早期外链 / 最近新增页 / 关键漏斗
流量策略: 截流或造势;首个精准渠道
立项后经营实验: MVP / 漏斗事件 / 预算上限 / 观察窗口 / 实际样本与局限 / 待验证假设
```
