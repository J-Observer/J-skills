## 段 6：外链

> **定预算之前先读** [`experiences/webcafe-topics.md`](../experiences/webcafe-topics.md) 五
> 与 [`experiences/webcafe-experiences-2.md`](../experiences/webcafe-experiences-2.md) 二十：
> 有 KD → 引荐域数量对照表（KD 30 需 36 个，KD 80 需 353 个）和一张导航站过滤清单；
> **外链买的是权重不是流量，所以不算 ROI**；短期暴增会被判定为 link scheme。

**分工**：执行全部路由到 `backlink` Skill；本段只判**什么时候发、发多少、发给哪个页面**。

### 硬规则（全文，含「为什么」；`SKILL.md` 只留摘要）

| 规则 | 为什么 |
|---|---|
| rankup 只判**什么时候发、发多少**；发现、填表、台账全在 `backlink` | 两个 Skill 各管一层，不在两处各存一份流程 |
| 候选站点调研判定**技术上可以对外提交**，只说明这个站没有硬伤、值得摆上桌，不代表这一轮就该把它排进提交队列；批量投递前必须把完整的候选清单摆给用户过一遍，等用户明确圈定这一轮实际要提交的子集，才能进入实际提交执行阶段 | 技术判定（存活状态、内容是否完整、是否占位页、是否公开产品）覆盖不到用户自己的曝光意愿与节奏考量——要不要让某个项目这一轮被公开曝光，这类判断只有用户能给；把技术清单默认当提交清单，等于拿技术判定替用户做了一次范围决策 |
| 节奏按 KD → 引荐域对照表；新词上线 2–4 周内不改页面 | 外链过快与频繁改页都会被读成操纵 |
| 302 / 307 不传权重；导航站按过滤清单筛；新后缀域名在老博客发的不算链接 | 这三条都是花了钱才知道的 |
| 每条外链进台账，证据阶梯 submitted → public → indexed 每级都要证据 | 没证据的外链等于没发 |

> 2026-09-30 合并：此表由原 `SKILL.md` 本段硬规则表下沉而来，同一条规则只在这里写全文。

### 什么时候发

| 判据 | 动作 |
|---|---|
| 段 5 未完成（索引没放开、sitemap 没提交） | 不发。指向 `noindex` 页面的外链是零 |
| 段 4 闸门有红灯 | 不发。先修站，外链把爬虫引来看到的是坏页 |
| 主目标页已被索引（`site:` 能查到）且排名在 20–50 之间 | 开始发，集中投给这一个页面 |
| 排名进前 10 且连续 5 天不动 | 减速，转向下一个目标页 |

### 输入

- 已上线且可交付价值的页面或产品。
- backlink 分析、竞品链接、目录、媒体、社区与合作伙伴机会。
- 目标受众、地区、品牌和合规约束。
- `.rankup/keywords.md` 里段 1 记录的目标关键词、对应页面及链接预算——这是本段外链投放的瞄准依据，不是另起一套目标。

### 必做动作

1. 使用 `backlink` 的分析参考评估链接质量、相关性、可达性和风险。
2. 使用 `backlink` 执行经授权的目录提交、触达和跟进；联络邮箱一律 `hello@<domain>`。
3. 逐项核对结果 URL、确认状态、审核要求、费用和错误信息；通用成功文案只能产生待复核候选。
4. 避免垃圾链接、误导性资料、重复提交和不透明付费方案。
5. 将已确认、待审核、失败、拒绝和下一步分别记录。
6. **链接预算不得在没有明确理由的情况下拆给多个目标词。** 段 1 给的链接预算是按单个词的
   难度反推的引用域区间；把它拆成几份分别投给几个词，结果是**任何一个词都够不到证据意义上的
   投入量**，观测窗口过后拿到的是「哪个词都没起色」，却分不清是外链不够还是选词本身就不成。
   要拆，先在 `.rankup/plan.md` 写清楚拆分理由（例如几个词共享同一 SERP 盘面，见
   `seo-webcafe.md`的市场口径要求），否则集中投给预算内排在
   最前的目标词。

### 两个应当最早做、且不花钱的渠道

新站的第一批外链**不必花钱**，先把这两条做掉——它们成本为零、可脚本化、
且都能被搜索引擎顺着爬到新站，缩短冷启动。

7. **公开代码仓库的 README。** 建一个**另外的、公开的**仓库（不是段 3 那个私有主仓），把站点的每个内页作为真实链接写进 README。
   完全可脚本化（仓库 CLI + git，不需要浏览器）。三条判据：
   - **仓库必须真的有用。** 只为挂链接建的空壳，是所有指南都点名的那种东西。
   - **所有外链锚点都是 `nofollow`**（实测一页 46 个锚点无一例外，连仓库描述与主页字段也是）。
     它买的是**收录加速与可核对性**，不是权重——把预期建对。
   - **README 会无声腐坏**：站点合并过的旧 URL 会一直 301，人眼看不出来。
     站点 URL 集合一变，就拿线上 sitemap 与 README 逐条 diff 一次。

8. **产品发布平台（Product Hunt 一类）。** 它给的是曝光、推荐流量和种子用户。
   **完整 runbook 见 [product-launch.md](../product-launch.md)**——
   这条渠道只能正经发一次，踩坑的地方全在流程细节里，动手前整篇读一遍。

   三条压缩到这里的判据：
   - **账号形态是硬门槛，不是产品。** 必须是看起来像真实用户的个人号；
     被判定为品牌号会导致发帖与评论被禁用。**这要在动手前问站主，不是发现问题时才问。**
   - **只能正经发一次。** 画廊图至少 3 张真实产品截图，宁可晚一天带齐再发。
   - **`rel` 要实测再记账**，发布前不入 `free-channels.json`——没发布就没有可观测对象。

   ⚠️ **一条曾经写错并已推翻的规则**（2026-08-22）：旧版这里写「浏览器自动化连接器
   通常无法为 file input 设置文件，把图交给用户拖是正确的分工」。**这是错的。**
   走 CDP 写 file input 确实被拒，但**带专用文件上传工具的连接器一次调用就成**
   （实测 4 个文件 786KB）。教训是通用的：**一个工具返回 `Not allowed`，
   证明的是那个工具的边界，不是任务的边界**——宣告 external-blocker 之前
   必须先枚举同类能力的其它入口。

### 步骤 check

**每步做完就核，不要攒到闸门再一起补。** 闸门（[`checklists.md`](../checklists.md)）判的是「这个环节能不能算完」，下表判的是「这一步做对了没有」——闸门过不了，一定是下面某一行没过。

| 步 | 客观通过条件 | 证据 |
|---|---|---|
| 0 | 发之前核过「什么时候发」表：目标页已被索引、段 4 无红灯；**没有给 `noindex` 或未索引页发外链** | `.rankup/plan.md` |
| 1 | 每个目标站的质量、相关性、可达性、风险四项都判过，**DR 低不构成自动否决，相关性差也不构成自动通过** | `.rankup/integrations.md` |
| 2 | 提交与触达都在授权范围内执行，**没有绕过登录、CAPTCHA、付费墙或反垃圾控制**；联络邮箱是 `hello@<domain>` | 同上 |
| 3 | 每一项都核对了结果 URL、确认状态、审核要求、费用、错误信息；**通用成功文案只产生待复核候选，不算成功** | 同上 |
| 4 | 没有垃圾链接、误导性资料、重复提交、不透明付费方案 | 同上 |
| 5 | 已确认 / 待审核 / 失败 / 拒绝 / 下一步**分别**记录，没有合并成一个「已提交」 | 同上 |
| 6 | 链接预算集中投给预算内排最前的词；若拆分，`plan.md` 里写了拆分理由 | `.rankup/plan.md` |
| 7 | 公开仓库 README 渠道：仓库**本身有用**（不是挂链接的空壳）、与私有主仓分开、锚点已实测确认是 `nofollow`、README 与线上 sitemap 逐条 diff 过 | `.rankup/integrations.md` |
| 8 | 产品发布平台：账号形态**动手前**问过站主（品牌号会被禁用发帖与评论）、画廊图 ≥3 张真实截图、`rel` 发布后实测再记账 | `.rankup/integrations.md` |

### 完成门禁

每项分发都有目标、执行证据、实际结果 URL 或明确审核状态和下一步；不得把表单提交、成功关键词命中或待付费页面报告为已获得有效外链。链接预算若被拆分给多个目标词，`.rankup/plan.md` 里有明确拆分理由。

### 交给下一段的

| 交给下一段的 | 下一段会怎么用它 | 如果这项缺失会怎样 |
|---|---|---|
| 已确认/待审核外链清单及其目标关键词/页面 | 段 7 把这份清单和段 1 的目标词、段 4 的基线放在一起看，判断排名变化能不能归因到外链 | 段 7 看到排名波动却不知道对应哪批外链投放，只能归因到「不知道什么原因」 |
